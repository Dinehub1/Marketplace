# Mediation setup — AdMob host, AppLovin + InMobi bidding

Decided 2026-09-28. AdMob runs the auction; AppLovin and InMobi bid inside it. For each
impression, every linked network (and AdMob's own demand) bids in real time and the
highest bid wins. Nothing in the app picks the winner.

## What the code already does

| Piece | Where |
|---|---|
| Native adapters (Android + iOS), versions pinned to the AdMob SDK the RN library links | `apps/mobile/plugins/with-ad-mediation.js` |
| Which networks a build carries: `EXPO_PUBLIC_AD_MEDIATION` (default `applovin,inmobi`; use `inmobi` for a child-directed app, since AppLovin is not Families-certified) | `apps/mobile/app.config.ts` |
| SKAdNetwork ids for Google + AppLovin + InMobi (162), regenerated by `node scripts/sync-skadnetwork-ids.mjs` | `apps/mobile/plugins/skadnetwork-ids.json` |
| Impressions logged as `network: "unknown"` once bidders are linked, because the RN library can't name the winner | `apps/mobile/lib/ads/adapters/admob.ts` |
| app-ads.txt lines for the bidders (paste their blocks here) | `apps/web/app/developer/app-ads-partners.ts` |
| Privacy policy names AppLovin and InMobi | `apps/web/app/developer/catalog.ts` → `AD_SDKS` |
| Per-network daily revenue from AdMob's mediation report | `supabase/migrations/20260928000000_ad_source_daily.sql`, `apps/web/lib/admob-report.ts`, `POST /api/admin/ad-source-sync` |

Consent needs no extra code: both adapters read the UMP consent the AdMob adapter
already gathers.

## What you need to do (dashboards)

1. **AppLovin account** (dash.applovin.com). An individual is fine; payouts go through
   Tipalti and need a W-8BEN. Copy the **SDK Key** (Account → Keys).
2. **InMobi account** (publisher.inmobi.com). Add each app, and create placements with
   **Google SDK Bidding** enabled. Bidding access may need your InMobi account manager.
   Note the **Account ID** (Finance → Payment Settings) and each **Placement ID**. For
   India payouts, either give a GST number or email a GST-exemption declaration to
   bd-finance@inmobi.com.
3. **AdMob → Mediation → create a mediation group** per format (rewarded, interstitial)
   and platform. Under **Bidding**, add **AppLovin** (SDK Key) and **InMobi** (Account ID
   + Placement ID). Accept each bidding partnership agreement. Leave waterfall empty.
4. **app-ads.txt**: paste AppLovin's and InMobi's blocks into `app-ads-partners.ts` and
   deploy. InMobi's crawler only starts after ~10,000 bid requests.
5. **AdMob API access** (for the per-network report):
   - In Google Cloud, enable the **AdMob API** and create an OAuth client (Web
     application; add `https://developers.google.com/oauthplayground` as a redirect URI).
   - In the OAuth 2.0 Playground, use your own client id/secret, authorise the scope
     `https://www.googleapis.com/auth/admob.readonly` as the AdMob account owner, and
     exchange the code for a **refresh token**.
   - Set `ADMOB_CLIENT_ID`, `ADMOB_CLIENT_SECRET`, `ADMOB_REFRESH_TOKEN` (and the existing
     `ADMOB_PUBLISHER_ID`) on the server.
6. **Apply the migration** `20260928000000_ad_source_daily.sql` to Supabase.
7. **Schedule the sync once a day**:
   `curl -X POST -H "x-admin-token: $ADMIN_TOKEN" https://<api-host>/api/admin/ad-source-sync`
   (`?days=90` for a one-off backfill). On Vercel, a cron hitting the same path with
   `CRON_SECRET` set also works.
8. **Store forms**: add AppLovin and InMobi to the Play Data Safety form and the App
   Store privacy answers.

## Reading the result

```sql
select network, format, country, sum(impressions) impressions,
       sum(earnings_micros) / 1e6 as usd,
       sum(earnings_micros) * 1000 / nullif(sum(impressions), 0) / 1e6 as ecpm_usd
from ad_source_performance
where day >= current_date - 30
group by 1, 2, 3
order by usd desc;
```

## Testing

With demo ad units, AdMob serves only its own test ads. To see a bidder win, register a
test device in AdMob, turn on test mode in that network's dashboard, and use **Ad
Inspector → single ad source testing** ("AppLovin (Bidding)", "InMobi (Bidding)").

## Upgrading

The adapter pins must match the AdMob SDK that `react-native-google-mobile-ads` links
(currently Android `play-services-ads` 25.4.0, iOS `Google-Mobile-Ads-SDK` 13.5.0). When
you bump the RN library, re-check each adapter's POM and podspec, then bump them together.
